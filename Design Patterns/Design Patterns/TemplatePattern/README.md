## 📌 Covered Design Patterns

### 🔹 Creational Patterns
*How objects are created*

- 🔒 **Singleton Pattern** – Ensure a single instance with global access
- 🏭 **Factory Pattern** – Encapsulate object creation logic
- 🔨 **Builder Pattern** – Construct complex objects step by step
- 🧬 **Prototype Pattern** – Create objects by cloning existing ones

### 🔹 Structural Patterns
*How objects are composed*

- 🔌 **Adapter Pattern** – Make incompatible interfaces work together
- 🛡️ **Proxy Pattern** – Control access to an object
- 🎁 **Decorator Pattern** – Add behavior dynamically without modifying classes

### 🔹 Behavioral Patterns
*How objects interact*

- 👁️ **Observer Pattern** – One-to-many dependency and automatic notifications
- 🎮 **Command Pattern** – Encapsulate requests as objects and decouple the sender from the receiver
- 📋 **Template Method Pattern** – Define the skeleton of an algorithm and allow subclasses to customize specific steps

## 📚 Pattern Categories Explained

### 🏗️ Creational Patterns
Focus on **object creation mechanisms**, trying to create objects in a manner suitable to the situation. They help make a system independent of how its objects are created, composed, and represented.

### 🔧 Structural Patterns
Concerned with **how classes and objects are composed** to form larger structures. They help ensure that if one part of a system changes, the entire structure doesn't need to change.

### ⚡ Behavioral Patterns
Deal with **algorithms and the assignment of responsibilities** between objects. They help define the communication between objects and make the interaction between objects more flexible.
